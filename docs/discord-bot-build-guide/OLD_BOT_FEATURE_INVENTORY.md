# Old bot feature inventory

## Source and scope

The only Python Discord bot available for this review lives in the connected transfer folder
(`main.py`, `cogs/*.py`, `configs/config.json`). It is **not** a Slice bot. It is a `discord.py 1.6.0`
(2021-era, prefix-command, Python 3.8) bot built for a Discord community/game server branded
**"Infria"** (`play.Infria.com`), reading as a FiveM/GTA-style roleplay server: gang/faction
management, a Tebex donation-store integration, tickets, moderation, verification, giveaways, and a
"trailer" (in-game perk) submission workflow. This was confirmed with the user, who directed that it
be treated as the old bot for this review even though it predates and is unrelated to Slice's
marketplace product. Its value here is as a **behavioral reference for generic Discord-community
infrastructure** (tickets, moderation, verification patterns, error handling), not as a predecessor
to any Slice-specific feature.

**Runtime facts:** `discord.py==1.6.0`, `aiomysql`, `pymysql`, `chat_exporter`, `jishaku` (owner-level
live eval console loaded for two hardcoded owner Discord IDs), `Intents.all()`, prefix `!`, no slash
commands, no context menus, no modals, no persistent views (all interaction is via message-reactions
and `bot.wait_for`), no automated tests, no CI, no `.env` — all configuration lives in
`configs/config.json` (48KB, embed text/IDs) and hardcoded values in source.

**Critical security findings (independent of migration decisions, listed once here):**

1. `cogs/SQL.py` hardcodes a live-looking production MySQL host, username, password, and database
   name directly in source (`SQLonStart.__init__`). This is a severe credential-leak risk — plaintext
   database credentials committed to a bot's source tree. Not reproduced in this document.
2. `cogs/Tebex.py` hardcodes a Tebex store API secret directly in source (`self.key = '9e6d...'`),
   used unauthenticated-by-config for payment lookups and gift card mutations.
3. `cogs/SQL.py` builds its connection pool with `asyncio.get_event_loop()` +
   `loop.run_until_complete(...)` executed at **import time**, outside any async context manager —
   a deprecated/fragile pattern that breaks on modern Python asyncio loop-policy changes.
4. All persistence is raw string-interpolated-adjacent parameterized MySQL (`%s` placeholders via
   `aiomysql`) with no ORM, migrations, or schema versioning; several queries below concatenate
   attacker-controlled data into `INSERT ... VALUE` tuples without server-side validation beyond
   Discord's own type converters.
5. `Main.help` explicitly gates the full command list behind `ban_members` permission with the
   in-code comment "so people can't steal ideas" — obscurity-as-security, not a real access control.
6. `AutoModerator.on_message` deletes any message containing a generic URL from non-moderators
   (except one hardcoded channel ID and ticket channels) with no allowlist, appeal path, or logging
   beyond a DM to the muted user on invite-links specifically.

None of these should be carried into the new bot even where the underlying feature is preserved.

## Summary counts

- **REMOVE:** 12 features (bootstrap, role add/remove, mass member backfill, custom help gating,
  gang/faction leaderboard, faction strikes, Tebex lookup/payments/giftcards, trailer perk system,
  raw MySQL pool) — all either Infria/game-specific with zero Slice relevance, or superseded by
  platform-native mechanisms.
- **REWRITE:** 14 features — mostly generic Discord-community infrastructure (tickets, moderation,
  auto-mod, giveaways, error handling, embed builder, confirmation helpers) whose *concept* is sound
  but whose implementation has bugs, missing permission checks, blocking patterns, or security
  issues that must not be carried forward.
- **MERGE:** 2 features (bug reports → tickets; freeform embed → announcement tooling).
- **PRESERVE (concept only):** several moderation primitives (kick/ban/mute/purge/warn/lockdown) and
  the embed-builder/confirmation-helper patterns — the *behavior* a staff team expects is reasonable,
  but every one is filed under REWRITE above because the concrete code must not be reused as-is.
- **UNKNOWN:** tempmute's actual expiry mechanism — no scheduler was found in the reviewed cogs that
  reads the `mutes.unmute` column, so this may already be non-functional in production. Flag for the
  client to confirm before assuming "auto-unmute" ever worked.

No feature in this bot is marked **REPLACE** in the sense of "a like-for-like Slice API already
exists" — because, as established, none of Infria's product-specific features (gangs, Tebex store,
trailer perks) have any Slice counterpart. Every Slice-relevant capability in the new bot (account
linking, marketplace, watchlist, notifications, collectors, vault) is being designed fresh in
BOT_PRODUCT_SPEC.md, informed by this bot only for its generic community-operations patterns.
