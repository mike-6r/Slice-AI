# Identity threat model

Credential stuffing, brute force, spraying, enumeration, refresh theft/replay, fixation, privilege escalation, status abuse, audit tampering, idempotency abuse, sensitive logging, reset-flow abuse, future cookie CSRF, XSS token exposure, and administrator compromise are recognized risks. Documents 001–004 now provide real PostgreSQL session/idempotency persistence, transaction-scoped audit writes, Argon2id hashing, opaque hashed refresh tokens, single-winner rotation, family revocation, Redis-backed auth limits, safe envelopes and dedicated HTTP E2E coverage. The post-004 remediation limits a revoked access token to an already-completed, fingerprint-matching logout-all replay; it cannot start a new mutation. Redis counter/TTL is atomic, unknown and known invalid logins each perform one configured verification, production cannot disable Secure refresh cookies, proxy trust is bounded by explicit hops, and malformed refresh-cookie encoding returns a safe 400.

Remaining technical debt: establish a retention/purge job for expired sessions/idempotency records, make post-commit token-signing failure revoke the just-created session, deduplicate repeated refresh-reuse audit writes, and evaluate keyed privacy hashes for low-entropy limiter dimensions. MFA, reset flows, CSRF for any future cross-site cookie topology, monitoring, administrator recovery, and wider platform rate limiting remain later-phase work.
